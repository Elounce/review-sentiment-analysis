## 1. Интерфейс и пользовательский опыт (Streamlit)
Срок реализации: 1–2 дня. Стек: Streamlit, Pandas, OpenPyXL.

- [ ] **Кнопки быстрой подстановки тестовых примеров**  
  Добавить на главный экран несколько кнопок с готовыми отзывами (развернутый позитивный, скрытый негатив с отрицанием, отзыв с молодежным сленгом, нейтральный текст). Это позволит демонстрировать работу классификатора комиссии в один клик без ручного набора с клавиатуры.
- [ ] **Форматированный экспорт отчетов в Excel (.xlsx)**  
  Заменить базовый CSV на скачивание полноценного Excel-файла с автоматической настройкой ширины колонок, подсветкой строк по цветам классов и листом со сводными метриками (доля позитива/нейтрала/негатива, средняя уверенность).
- [ ] **Генерация облака слов (WordCloud) по загруженному файлу**  
  Отрисовывать в отдельном блоке визуализацию наиболее частотных лемм отдельно для каждой категории отзывов, извлеченных из пользовательского файла.
- [ ] **Защита панели управления паролем администратора**  
  Скрыть кнопки переобучения модели и скачивания базы пользовательских исправлений (feedback.csv) в боковом меню под пароль, чтобы случайные посетители сайта не могли сбить рабочие веса модели.
- [ ] **Расчет текстовых метрик корпуса**  
  Показывать статистику по загруженным текстам: распределение длин отзывов (в символах и словах), минимальный и максимальный размер, а также коэффициент лексического разнообразия (Type-Token Ratio).

## 2. Машинное обучение и обработка текста (NLP)
Срок реализации: 3–5 дней. Стек: Scikit-Learn, SciPy, Matplotlib, Seaborn.

- [ ] **Интерактивное сравнение семейства байесовских моделей**  
  Добавить переключатель между вариантами классификатора:
  - ComplementNB — базовый вариант, оптимизированный под работу с несбалансированными классами;
  - MultinomialNB — классический мультиномиальный алгоритм;
  - BernoulliNB — бинарный учет встречаемости токенов;
  - LinearSVC / LogisticRegression — линейные бейзлайны для сравнения.  
  Выводить на экран таблицу со сравнительными метриками (F1-macro, точность, время инференса).
- [ ] **Вкладка оценки качества модели (Model Evaluation)**  
  Построить интерактивную матрицу ошибок (Confusion Matrix) через Seaborn/Matplotlib, графики Precision-Recall кривых и детальный отчет classification_report по фолдам кросс-валидации.
- [ ] **Калибровка вероятностей (Probability Calibration)**  
  Наивный Байес часто выдает избыточно завышенные или заниженные вероятности из-за предположения о независимости признаков. Использовать CalibratedClassifierCV (метод Платта или изотоническую регрессию), чтобы выдаваемый процент уверенности соответствовал реальной вероятности ошибки.
- [ ] **Специализированный словарь стоп-слов**  
  Очистить базовый русскоязычный список стоп-слов от маркеров отрицания (не, нет, ни, без), усилителей (очень, сильно, крайне, абсолютно) и слов сомнения (вроде, кажется), чтобы снизить размерность TF-IDF матрицы без потери смысловых акцентов.

## 3. Аспектный анализ тональности (Aspect-Based Sentiment Analysis)
Срок реализации: 1–2 недели. Стек: Spacy, NLTK, Scikit-Learn.

В реальных отзывах пользователи часто дают смешанную оценку («Наушники звучат отлично, но провод перетерся через неделю, а доставка задержалась»). Классификация всего текста одной общей меткой теряет эти детали.

- [ ] **Выделение смысловых категорий (аспектов)**  
  Разбивать отзыв на независимые оценки по ключевым направлениям:
  - Качество товара и материалы;
  - Доставка, сроки и упаковка;
  - Соответствие цене;
  - Работа службы поддержки и сервис.
- [ ] **Обучение отдельных байесовских классификаторов под каждый аспект**  
  Каждое предложение или фрагмент текста привязывается к аспекту и оценивается отдельно.
- [ ] **Лепестковая диаграмма (Radar Chart) в интерфейсе**  
  Отображать профиль товара в виде паутинки, наглядно показывающей сильные и проблемные зоны по мнению покупателей.

## 4. Бэкенд и микросервисная архитектура (FastAPI, PostgreSQL, Celery)
Срок реализации: 1–2 недели. Стек: FastAPI, PostgreSQL, SQLAlchemy, Celery, Redis.

Переход от монолитного приложения на Streamlit к раздельной архитектуре «бэкенд-сервис + клиентский интерфейс».

Архитектурная схема:
```text
[Streamlit / Веб-клиенты / Telegram-бот]
                   │
                   ▼  (REST API / JSON)
          [FastAPI Сервер]
          ├── /api/v1/predict          (быстрый синхронный инференс)
          ├── /api/v1/predict-batch    (постановка больших файлов в очередь)
          └── /api/v1/retrain          (фоновый запуск дообучения)
                   │
         ┌─────────┴─────────┐
         ▼                   ▼
    [PostgreSQL]       [Celery Worker + Redis]
  (база отзывов,        (асинхронная обработка
   метки, пользователи)  тяжелых задач и парсинга)
```

- [ ] **REST API на FastAPI**  
  - Эндпоинты `/api/v1/predict` (одиночный текст), `/api/v1/predict-batch` (массивы текстов и файлы), `/api/v1/explain` (интерпретация решения модели).
  - Валидация входных данных через схемы Pydantic v2 и автоматическая Swagger-документация по адресу `/docs`.
- [ ] **Интеграция реляционной базы данных (PostgreSQL)**  
  - Замена плоских CSV-файлов на таблицы: reviews, predictions, feedback, model_versions.
  - Управление миграциями структуры БД через Alembic.
- [ ] **Асинхронные фоновые задачи (Celery + Redis)**  
  - Пакетная обработка файлов на десятки тысяч строк без блокировки веб-интерфейса, с передачей статуса прогресса клиенту.
- [ ] **Telegram-бот для экспресс-проверки**  
  - Бот, подключенный к общему API, в который можно переслать текст отзыва или ссылку и получить оценку тональности с ключевыми словами прямо в мессенджере.

## 5. Сбор данных и активное дообучение (Active Learning)
Срок реализации: 2–3 недели. Стек: Playwright, Beautiful Soup, Docker, DVC.

- [ ] **Парсер отзывов с торговых площадок**  
  Модуль сбора отзывов по прямой ссылке на товар (Wildberries, Ozon, Яндекс.Маркет) для демонстрации работы системы на реальных сырых потоках данных.
- [ ] **Активное машинное обучение со стратегией Uncertainty Sampling**  
  Алгоритм фильтрует входящий поток неразмеченных отзывов и отбирает для ручной проверки человеком только те примеры, в которых классификатор наименее уверен (энтропия распределения вероятностей максимальна, предсказание колеблется около 33% для каждого класса). Это позволяет улучшать модель минимальным числом размеченных вручную строк.
- [ ] **Контейнеризация проекта (Docker / Docker Compose)**  
  Написание Dockerfile и docker-compose.yml для развертывания веб-интерфейса, API, базы данных и воркеров одной командой docker compose up -d.

## 6. Экспериментальное исследование для доклада и диплома
Срок реализации: 1 неделя. Стек: PyTorch, Hugging Face Transformers, CatBoost.

Экспериментальный раздел, закрывающий главный вопрос комиссии: «Почему для задачи выбран классический наивный Байес, а не современные нейросети-трансформеры?».

- [ ] **Сравнительный бенчмарк разнородных архитектур**  
  Провести обучение и тестирование на едином корпусе для четырех подходов:
  1. ComplementNB (наш основной метод);
  2. LogisticRegression (линейная модель);
  3. CatBoost или LightGBM (градиентный бустинг над TF-IDF признаками);
  4. RuBERT-tiny2 (компактная предобученная нейросеть-трансформер).
- [ ] **Сводная таблица компромиссов (Trade-off Analysis)**  
  Сопоставить подходы по пяти измеримым критериям:
  - Итоговое качество (Macro F1-Score);
  - Скорость обработки на CPU (миллисекунды на 1000 отзывов);
  - Потребление оперативной памяти во время инференса (RAM);
  - Размер весов модели на диске (МБ);
  - Требования к аппаратному обеспечению (работа на обычном офисном ПК без GPU).
- [ ] **Обоснование практической применимости**  
  Сформулировать вывод для доклада: в задачах высоконагруженной фильтрации потоков отзывов в реальном времени наивный Байес обеспечивает близкое к нейросетям качество при в сотни раз меньших затратах на серверную инфраструктуру.
